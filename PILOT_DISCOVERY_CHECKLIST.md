# AI Hotel — Pilot Discovery Checklist

## Property profile

- Hotel type.
- Number of rooms.
- Departments.
- Owner / director / GM structure.
- Current operating model.
- Single-property or multi-property context.

## Current systems

Identify the tools used for:
- PMS;
- channel manager / CRS;
- revenue management;
- guest messaging;
- POS / F&B;
- housekeeping;
- maintenance / work orders;
- CRM;
- accounting;
- HR / roster;
- telephony;
- reporting / BI;
- internal communication.

## Director workflow

Collect:
- morning routine;
- daily reports;
- recurring meetings;
- recurring decisions;
- recurring interruptions;
- approval rules;
- escalation rules;
- what the director checks remotely;
- what still requires physical presence.

## Guest workflow

Map:
- top request categories;
- current guest channels;
- how requests reach departments;
- where requests are delayed or lost;
- multilingual pain;
- which requests require payment or approval;
- how completion is confirmed today.

## First workflow selection

Select a small pilot set based on:
- frequency;
- management/staff time consumed;
- guest/revenue impact;
- integration difficulty;
- autonomy risk;
- measurable baseline;
- time-to-demo.

## Data access

Start with the safest available method:
1. sample reports;
2. sanitized exports;
3. read-only API;
4. controlled live integration;
5. limited low-risk actions after approval.

## Success metrics

Define before the pilot:
- director time saved;
- response time;
- unresolved incidents;
- SLA breaches;
- task completion accuracy;
- guest request completion;
- staff touches;
- guest satisfaction;
- revenue or cost impact;
- staff adoption;
- unauthorized action count.

## Red lines

Do not automate without explicit policy:
- payments;
- refunds;
- legal communications;
- HR decisions;
- staff discipline;
- access/security decisions;
- emergency/safety decisions;
- pricing changes;
- sensitive public guest replies.

## Policy and commercial ownership

- Identify who approves each service rule and when it takes effect.
- Separate hotel, residence, outlet and third-party service responsibilities.
- Identify the operator, contracting party and required property/group approvals.
- Confirm that the selected channel can verify the guest's authority.
- Determine language needs from actual guest and staff demand.

## Existing capability comparison

- Demonstrate the current workflow using the same evaluation cases.
- Check whether a licensed feature or configuration change addresses the need.
- Establish integration permissions and costs before committing to a build.
- Agree the baseline, sample and review process.
- Include staff supervision and correction time in the economic case.
